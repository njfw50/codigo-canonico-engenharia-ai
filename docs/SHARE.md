These are editorial invitations, not quotations or replacements for the canons. Adapt the introduction to the audience and your actual experience. Publication is a separate action chosen by the person sharing.

## Add a source badge to a README

Use this optional badge when the project is a reference for your work:

[![Reference: Canonical Protocol](../assets/canonical-reference.svg)](https://njfw50.github.io/canonical-engineering-ai/)

```markdown
[![Reference: Canonical Protocol](https://raw.githubusercontent.com/njfw50/codigo-canonico-engenharia-ai/main/assets/canonical-reference.svg)](https://njfw50.github.io/canonical-engineering-ai/)
```

The badge communicates a declared reference, not certification, a completed audit or an endorsement by another organization. Explain in your own project what you actually used.

## Share evidence with the introduction

Useful reports describe a real problem, the decision made, an observed result and a limitation. A negative result is useful too. Include the source commit/version so another person can reproduce the review. Follow [the contribution procedure](../CONTRIBUTING.md) for proposed changes and [the citation file](../CITATION.cff) for attribution.
